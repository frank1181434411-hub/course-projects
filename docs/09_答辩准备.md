# 答辩准备

## 1. 项目简介

Tank Battle 是一个基于 C++17 和 SFML 3.1.0 的复古坦克大战课程设计。当前版本实现了基础战斗、文本地图、地形碰撞、砖墙破坏、坦克互撞、基地阻挡、草地覆盖绘制、随机道具、简单/普通/困难 AI、菜单/HUD、局域网双人合作、贴图和音效接入。

## 2. 演示流程

1. 使用 MSYS2 UCRT64 打开项目目录。
2. 执行 Debug 配置和构建命令。
3. 启动 `TankBattle.exe`。
4. 展示主菜单、单人模式设置和地图选择。
5. 展示玩家移动、射击、敌人、炮弹、道具、基地和地图地形。
6. 展示砖墙破坏、地形阻挡、基地阻挡和草地覆盖效果。
7. 展示普通 AI 和困难 AI 在测试地图中的追击、射击位寻路和破墙攻击效果。
8. 展示 HUD、暂停、设置音量和胜负结算界面。
9. 如有两台设备，展示 Host Multiplayer 与 Join Multiplayer 的局域网发现和合作流程。
10. 说明当前已完成模块和后续可扩展模块。

## 3. 核心类说明

- `Game`：窗口、主循环、地图加载、实体容器、碰撞结算和状态判定。
- `Tank`：坦克公共基类。
- `PlayerTank`：玩家输入和道具效果。
- `EnemyTank`：轻型和重型敌人。
- `Bullet`：炮弹移动、伤害和归属。
- `Item`：血包和弹药强化包。
- `Base`：基地生命、绘制、受击和坦克移动阻挡。
- `Map` / `Tile`：文本地图加载、瓦片规则和分层绘制。
- `Collision`：地图阻挡、边界和炮弹命中瓦片查询。
- `AIController` / `EnemyAI`：敌方 AI 接口；当前 `EasyAI`、`NormalAI` 和 `HardAI` 已有初步实现。
- `NetworkSession`：主机、客户端、输入、快照和砖墙变化同步。
- `HostDiscovery`：UDP 主机广播和加入界面主机发现。
- `Hud`：显示玩家血量、生命数量占位和强化状态。
- `ResourceManager`：贴图、音效和全局音量管理。

## 4. 关键流程说明

程序启动后创建 `Game` 并加载文本地图。

地图中的实体标记具有以下含义：

- `P`：旧版玩家初始位置兼容标记；
- `X`：一号玩家初始位置；
- `Y`：二号玩家初始位置；
- `B`：基地位置；
- `L`：轻型敌方坦克初始位置；
- `H`：重型敌方坦克初始位置。

`Map` 在解析这些字符时记录实体位置，并将对应格子转换为空地。

地图加载完成后，`Game` 首先创建玩家和基地，然后遍历全部 `EnemySpawn` 数据，一次性创建轻型和重型敌方坦克。每辆敌人同时创建一个独立的 AI 控制器。

游戏不采用波次、分批刷新或死亡后补充机制。敌人被消灭后从敌人容器中删除，不会重新生成。当全部初始敌人被消灭后，游戏进入 `Victory` 状态。

进入主循环后，程序依次完成：

1. 处理窗口事件和玩家输入；
2. 更新玩家状态；
3. 构造 `AIContext`；
4. 调用各敌人 AI 生成 `TankCommand`；
5. 更新敌人移动和射击；
6. 更新炮弹和道具；
7. 执行地图、坦克、基地和炮弹碰撞判定；
8. 删除失效炮弹和死亡实体；
9. 更新胜利或失败状态；
10. 按地图底层、实体层和草地覆盖层的顺序绘制画面。

联机流程中，主机进入游戏后通过 UDP 广播房间信息；客户端在加入界面监听主机，选择后通过 TCP 连接。客户端发送输入，主机更新世界并发送快照，客户端应用快照显示同步结果。

## 6. 创新点

当前可说明的设计点包括：

- 使用继承组织玩家坦克和敌方坦克。
- 使用 ownerId 区分炮弹归属。
- 将部分原型参数集中在 `prototype` 命名空间中。
- 使用 `Map::drawLayer` 分离地图底层和草地上层。
- 使用 `boundsAt` 在坦克移动前预测下一步碰撞矩形。
- 使用 `TankCommand`、`AIContext` 和 `AIController` 分离敌人实体与 AI 决策。
- 普通 AI 使用玩家四方向射线上的权重 2 射击位作为追击目标；困难 AI 可在路径代价过大时考虑权重 1 射击位并攻击砖墙。
- 网络通信采用主机权威快照同步思路，便于避免客户端各自结算导致状态分歧。
- 使用 UDP 广播实现局域网房间发现。
- 使用 `ResourceManager` 统一管理贴图、音效和全局音量，并提供资源缺失回退。
- ### 文本地图驱动的敌人部署
项目使用文本地图同时描述地形和关卡初始部署。
`L` 和 `H` 分别表示轻型和重型敌方坦克，使关卡设计者可以直接通过修改地图文件调整：
- 敌人总数量；
- 轻型和重型敌人的比例；
- 各敌人的初始位置；
- 敌人与地图障碍物的空间关系。
这种设计将关卡数据与程序逻辑分离。修改敌人部署时不需要重新编写游戏代码，只需要调整地图文件。
同时，敌人物理类型与 AI 难度保持分离。同一个重型坦克既可以使用简单 AI，也可以使用普通或困难 AI，从而提高了系统的可配置性。

## 8. 现场修改预案

- 修改坦克速度：待配置系统完成后补充。
- 修改炮弹伤害：待配置系统完成后补充。
- 修改射击冷却：待配置系统完成后补充。
- 修改血包恢复量：待配置系统完成后补充。
- 修改强化时间：待配置系统完成后补充。
- 增加一种道具：需要扩展 `ItemType` 和 `PlayerTank::collectItem`。
- 修改敌人数量：通过编辑地图中的 `L/H` 标记完成。
- 修改 AI 决策参数：可在 `enemy_ai.hpp` 和 `src/ai/enemy_ai.cpp` 中调整决策间隔、受阻时间、开火误差和射击位选择规则。
- 修改地图：编辑 `assets/maps/single/` 或 `assets/maps/coop/` 下的文本地图。
- 修改按键：待输入配置系统完成后补充。
- ### 修改敌人数量和类型
敌人数量和类型不需要在 C++ 代码中修改，而是通过编辑文本地图完成。
- 增加一个 `L`：增加一辆轻型敌方坦克。
- 删除一个 `L`：减少一辆轻型敌方坦克。
- 增加一个 `H`：增加一辆重型敌方坦克。
- 删除一个 `H`：减少一辆重型敌方坦克。
- 移动 `L` 或 `H`：修改对应敌人的初始位置。
地图中的 `L/H` 只决定敌人的物理类型，不决定 AI 难度。AI 难度仍由游戏设置统一选择。
