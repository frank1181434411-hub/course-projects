# 模块详细设计

## Game

### 1. 职责

管理窗口、主循环、实体容器、输入事件、更新、渲染和最小胜负判定。

### 2. 当前文件

- `include/core/game.hpp`
- `src/core/game.cpp`

### 3. 当前类和接口

- `Game::Game()`
- `Game::run()`
- `Game::startHost`
- `Game::joinHost`
- `Game::leaveNetworkGame`

### 4. 已实现功能

创建窗口，显示主菜单，加载所选地图，根据地图出生点生成玩家、基地和敌人；持有 `ItemSpawner` 并随机生成道具；为每个敌人创建独立 AI 控制器；更新玩家、敌人、道具、炮弹；处理地形碰撞、坦克碰撞、基地阻挡、炮弹伤害、砖墙破坏；判断胜利和失败。当前还实现离线、主机和客户端三种更新流程，以及网络输入、快照应用、快照创建和 UI 渲染接口。

### 5. 尚未实现功能

配置驱动、断线恢复、延迟补偿、玩家复活和完整关卡管理。

### 6. 与其他模块的关系

持有 `Map`、`NetworkSession`、`HostDiscovery`、各类 UI 菜单、`PlayerTank`、`Base`、`EnemyTank`、`AIController`、`Bullet`、`Item` 和 `ItemSpawner`。

### 7. 后续修改点

建议后续拆分 `World` 和更细的状态机。敌人不再需要独立波次生成器，当前采用地图 `L/H` 标记一次性初始化。

## 地图模块

### 1. 职责

负责地图数据、文本地图加载、地形绘制、瓦片规则和实体初始部署数据解析。

地图模块需要记录玩家初始位置、基地位置，以及全部轻型和重型敌人的初始位置。敌人数量和类型直接由地图文件决定。

### 2. 当前文件

- `include/world/map.hpp`
- `src/world/map.cpp`
- `include/world/tile.hpp`
- `src/world/tile.cpp`

### 3. 设计类型和接口

当前已有：

```cpp
struct EnemySpawn
{
    sf::Vector2f position;
    EnemyType type=EnemyType::Light;
};
```

`Map` 对外提供：

```cpp
const sf::Vector2f& playerSpawn() const noexcept;
const sf::Vector2f& basePosition() const noexcept;
const std::vector<EnemySpawn>& enemySpawns() const noexcept;
```

继续保留：

- `TileType`
- `Tile`
- `Map`
- `Map::loadFromFile`
- `Map::loadFromLines`
- `Map::tileAt`
- `Map::setTile`
- `Map::tilePosition`
- `Map::tileCenter`
- `Map::draw`
- `Map::drawLayer`

### 4. 地图字符约定

| 字符 | 含义 | 解析结果 |
| --- | --- | --- |
| `.` 或空格 | 空地 | `TileType::Empty` |
| `#` | 砖墙 | `TileType::Brick` |
| `S` | 钢墙 | `TileType::Steel` |
| `W` | 水域 | `TileType::Water` |
| `G` | 草地 | `TileType::Grass` |
| `P` | 旧版玩家初始位置兼容标记 | 记录位置后转换为空地 |
| `X` | 一号玩家初始位置 | 记录位置后转换为空地 |
| `Y` | 二号玩家初始位置 | 记录位置后转换为空地 |
| `B` | 基地位置 | 记录位置后转换为空地 |
| `L` | 轻型敌人初始位置 | 保存 `EnemyType::Light` 后转换为空地 |
| `H` | 重型敌人初始位置 | 保存 `EnemyType::Heavy` 后转换为空地 |

原通用敌人标记 `E` 停止使用。

### 5. 敌人初始化流程

`Map` 只负责解析和保存敌人初始部署，不直接创建 `EnemyTank`。

`Game` 在地图加载完成后遍历：

```cpp
map_.enemySpawns()
```

并按照每个 `EnemySpawn` 的位置和类型一次性创建敌人。

每个敌人同时创建一个独立的 `AIController`。AI 难度由游戏模式或难度配置决定，不由 `L/H` 字符决定。

### 6. 地图合法性要求

地图加载时应检查：

- 玩家初始位置存在。
- 基地位置存在。
- 至少存在一个 `L` 或 `H`。
- 所有实体标记位于地图范围内。
- 不存在无法识别的旧 `E` 标记。
- 实体初始位置不能与不可通行地形重叠。
- 同一个地图格不能同时表示多个实体。

### 7. 与其他模块的关系

`Game` 使用地图模块创建玩家、基地和全部初始敌人，并在运行阶段查询地形碰撞和绘制地图。

AI 模块使用地图进行可通行性判断、射击视线检查和路径搜索。

### 8. 后续修改点

继续补充地图合法性检查和更多地图测试。地图编辑器不在本项目范围内。
